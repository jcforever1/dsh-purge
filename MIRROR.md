## The one change to the code

`package.json` no longer declares:

```json
"postinstall": "node scripts/ensure-profile-bundle.mjs"
```

**Why.** That script appends `dsh-purge` to a profile's `dsh.profile.bundles` list. DSH's own
plugin manager already does exactly this — in `dsh-plugin-manager`, `reconcile()` runs after every
install the manager performs, adds the new bundle to `dsh.profile.bundles`, and loads the bundle's
`cordis.patch.yml` as an overlay patch. The script is therefore redundant on the market path
(Discover → Install) and on any manager-driven install.

**Why it matters.** pnpm 11 refuses to run a dependency's lifecycle script until the exact
dependency is allowed. The key pnpm demands is the dependency's *resolved* identifier, and for a
git dependency that identifier embeds the commit:

```
dsh-purge@https://codeload.github.com/<owner>/dsh-purge/tar.gz/<commit>
```

A name-only key is not accepted (verified against pnpm 11.28.5: `allowBuilds: { dsh-purge: true }`
still fails with `ERR_PNPM_IGNORED_BUILDS`). The commit is part of the key, so the key changes on
every release and every existing user has to approve the install scripts again on every update.

With the script removed, a market install runs **zero** lifecycle scripts: no approval, no
`allowBuilds` entry, at any version, for any user.

**What is unaffected.** The script itself is still in this repository and still ships in the
package (`scripts` is in the `files` list). It is only no longer wired to `postinstall`. Install
through Discover or the plugin manager and the bundle is registered for you. Install through raw
pnpm — `dsh plugin --profile <profile> add …` — and the CLI path bypasses the plugin manager, so
run the script once by hand:

```bash
node <profile>/node_modules/dsh-purge/scripts/ensure-profile-bundle.mjs
```

## The market index

`index.json` in this repository is a DSH plugin market index, format 1. Add this URL in
**Settings → Plugin Market → Index sources**:

```
https://raw.githubusercontent.com/jcforever1/dsh-purge/master/index.json
```

`index.json` is generated by `make-index.mjs` and committed by `.github/workflows/update-index.yml`.
The index pins one commit of this repository, so every install lands on exactly one tree.

To regenerate it locally:

```bash
npm install @deepseek-ai/dsh-plugin-market-index@0.2.1-rc.2 semver
node make-index.mjs --repo jcforever1/dsh-purge --ref master --out index.json
```

The generator refuses to write an index that fails the validator DSH itself ships
(`@deepseek-ai/dsh-plugin-market-index`).

## Staying in sync with upstream

`.github/workflows/sync-upstream.yml` pulls upstream `master` into this mirror every six hours,
re-applies the single change above, regenerates the index, and commits. Files this mirror owns
(`index.json`, `make-index.mjs`, `MIRROR.md`, `mirror-notice.md`, the two workflows) are excluded
from the sync.
